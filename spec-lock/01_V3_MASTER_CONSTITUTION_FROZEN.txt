============================================================
H. CANONICAL HASH LIBRARY
============================================================

THIS IS CRITICAL.

Create ONE package/module for canonical hashing and canonical serialization.
No subsystem may independently redefine hash inputs, normalization, ordering, or separators.

All hash functions use stable deterministic serialization and SHA-256.

CANONICAL HASH DOMAINS:

1. productValuesHash()
Semantic Product values only.
Excludes provenance, actors, timestamps, verification state, and revision metadata.
Used by semantic Product compatibility and any AI analysis whose interpretation depends on what the Product is.

2. factAuthorityHash()
Exact fact values + provenance + source/evidence identity + USER_VERIFIED authority state.
Verification-only changes MAY change this hash without changing productValuesHash.

3. claimSetHash()
Exact claim identities/text/risk/evidence/authorization state.

4. revisionSnapshotHash()
Complete immutable ProductRevision audit identity.
Includes productValuesHash, factAuthorityHash, claimSetHash and immutable revision metadata as defined by the canonical serializer.
NEVER use revisionSnapshotHash as a universal downstream invalidation key.

5. rawAssetManifestHash()
Exact frozen physical asset truth only:
assetId + assetSha256 + roleAtFreeze + availabilityAtFreeze + render-safe physical metadata required by the contract.
No AI analysis identity belongs in this hash.

6. assetAnalysisInputHash()
workspaceId + productId + assetSha256 + productValuesHash +
provider + model + promptVersion + analyzerVersion/schemaVersion.

7. analysisContextHash()
Exact frozen set of validated AssetAnalysis identities and their physical/provider/schema bindings +
rawAssetManifestHash + productValuesHash.

8. creativeTextHash()
Canonical final creative semantic/copy identity as defined by the creative contract:
concept/angle where relevant + hook + script + CTA + final spoken/subtitle text used by production gates.

9. scriptHash()
Exact production spoken-copy identity only:
canonical hook + canonical script + canonical CTA.
Use ONE canonical function everywhere.
Never hash script body only in one subsystem and hook+script+CTA in another.

SCRIPT IDENTITY NORMALIZATION IS SEMANTIC-PRESERVING ONLY:
- Unicode NFC
- deterministic line-ending normalization
- deterministic whitespace/separator normalization
- preserve actual words, Arabic orthography, digits, punctuation semantics, and intended spoken text
- DO NOT remove Arabic diacritics for identity
- DO NOT fold Arabic letters for identity
- DO NOT convert digits to words for identity

Arabic/ASR tolerant matching uses a SEPARATE alignment-normalization contract in Section AX.
The alignment matcher MUST NOT redefine scriptHash.

10. audioHash()
SHA-256 over exact real audio bytes.

11. alignmentHash()
Exact validated alignment content + audioHash + scriptHash + provider/model/version + alignmentNormalizationProfileVersion.

12. timelineHash()
Exact canonical MasterTimeline content.

13. scenePlanHash()
Exact canonical ScenePlan content + exact bound asset/segment/AI-media references.

14. renderInputHash()
Everything that can physically change the rendered output, including exact timeline, scene plan, media hashes, captions/style, render settings, and selected audio.

15. renderOutputHash()
SHA-256 over exact final rendered bytes.

MISSING HASH / LEGACY NULL RULE:

A missing required canonical hash is INCOMPATIBLE.
Patterns such as:
!hash || compatible
are forbidden in production compatibility checks.

A legacy artifact without a required binding may only be used after deterministic backfill from immutable source data.
If exact backfill is impossible:
STALE / INCOMPATIBLE.

HASH DEPENDENCY RULE:

Downstream artifacts bind only to the hashes they semantically depend on.
A verification-only change must not force physical asset re-ingestion or multimodal re-analysis when productValuesHash and physical bytes are unchanged.
A semantic Product value change must invalidate Product-dependent analyses even when asset bytes are unchanged.

- normalize punctuation/separators for comparison
